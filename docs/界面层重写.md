# 界面层重写：Compose for TV

重写日期：2026 年 10 月 24 日。版本：0.3.0（versionCode 3）。首轮替换 `app/ui` 与 `MainActivity` 的表现层；0.4.0 起播放器控制层也改为 Compose（见“播放器”一节），视频画面、弹幕与字幕渲染仍是 View。

## 为什么重写

0.2.0 的页面是程序生成的纵向文字列表（`LinearLayout` + `TextView`），没有图片加载能力，无法呈现封面、海报墙和焦点放大等 TV 典型交互。原版产品的首页是每周番剧海报，用户要求以“最符合 TV 的交互细节和动画”重做，因此选用 Compose for TV（`androidx.tv:tv-material`）整体重写。

## 技术选型

| 组件 | 版本 | 用途 |
| --- | --- | --- |
| Compose BOM | 2026.06.01（Compose 1.11.4） | 基础 UI、焦点、动画、LazyRow/Grid |
| androidx.tv:tv-material | 1.1.0 | `Card`、`ListItem`、`Button`、`Switch`，自带焦点缩放、边框与光晕 |
| Coil 3 | 3.5.0 | 封面图加载，内存缓存 12%，磁盘缓存 128 MB |
| activity-compose | 1.13.0 | `setContent`、`BackHandler` |
| lifecycle-runtime-compose | 2.10.0 | 生命周期感知 |

版本选择受 `compileSdk 36` 限制：Compose 1.12 / Coil 3.6 要求 compileSdk 37，暂不升级。

## 结构

```text
app/ui/
  TvHost.kt          页面与宿主 Activity 的边界：播放、系统选择器、手机表单、提示、后台执行
  Navigator.kt       四个栏目各自的路由栈；Route 携带页面数据并提供稳定 key
  TvApp.kt           应用外壳：左侧导航 + AnimatedContent 路由切换 + 应用内提示
  theme/TvTheme.kt   颜色、十英尺字号、圆角、尺寸常量
  components/        Cards（海报卡/横卡/入口卡）、ListRows（操作行/开关行/选项行）、Layout（页面骨架/行/加载/失败/空态/按钮）、NavRail、Dialogs、Async
  screens/           Home、Library*、MediaActions*、Anime*、Settings*、Subtitle*、Data*
```

### 导航与返回

- `Navigator` 持有 `tab` 与 `stack`，`switchTab` 清空栈。`direction` 决定转场方向：前进向左滑入，后退向右滑入。
- 每个路由由 `rememberSaveableStateHolder` 按 `route.key` 保存状态：目录页的过滤词、滚动位置、上次聚焦项在返回后恢复。
- 返回键顺序：先退子页面；栏目根页上内容区有焦点时把焦点交给左侧导航；导航上再按返回回到首页；首页再按返回退出。
- 离开页面时 `DisposableEffect` 取消属于该页面的手机表单，迟到的提交不作用于下一页。

### 焦点规则

- 每个页面声明初始焦点（`FocusRequester` + `LaunchedEffect`）：首页第一张卡、目录第一项、确认页的“取消”。
- `LazyRow` / `LazyColumn` / `LazyVerticalGrid` 加 `focusRestorer()`，上下行切换时回到该行上次的项。
- 列表页用 `rememberSaveable` 记住上次聚焦的条目 ID，返回时先 `scrollToItem` 再请求焦点。
- 左侧导航：焦点落到某栏目即切换，不需要按确定；无焦点时折叠为图标，有焦点时展开文字（220 ms）。
- 视频行：确定播放，长按打开“文件操作”，行尾常驻“长按：操作”提示。
- 破坏性操作初始焦点在“取消”，主按钮为红色。

### 动画

- 卡片焦点：放大 1.05–1.08、3 dp 青色边框、光晕；标题颜色 160 ms 过渡。
- 海报墙顶部：焦点项的海报右侧模糊放大作背景，420 ms 淡入淡出；标题与简介 240 ms 切换。
- 页面切换：220 ms 淡入 + 260 ms 轻微水平位移。
- 进度条、提示浮层均有补间动画；加载态延迟 250 ms 显示，避免闪烁。

### 异步与状态

- `rememberLoader(keys) { }` 在 IO 线程读取，返回 `Load.Loading / Ready / Failed`，离开页面自动取消；`reload()` 重试。
- `rememberActions()` 处理保存、删除、下载等一次性操作，同一页面同时只允许一个在飞。
- `TvHost.refreshEpoch` 在从播放器返回或系统选择器完成后递增，依赖观看记录的页面以此重新读取。

## 焦点规则补充（0.3.0 后续）

- 从内容区发起的页面切换（push / pop / 内容内切栏目）期间，旧页面被移除时系统会把焦点临时交给导航栏；`FocusGate.pendingContentFocus` 标记这段时间，导航栏不把它当作用户选择，新页面的初始焦点照常生效。
- 向左离开内容区时保存当前聚焦项（`saveFocusedChild`）；在导航栏按右键时先恢复它，失败再用页面声明的初始项，不使用几何最近项。
- 设置类可滚动页面返回时由容器的 `focusRestorer` 恢复到原来的行；首页与番剧栏目的海报墙用 `WallFocus` 显式记住“行 + 卡片”，数据就绪后再恢复，避免加载期间的回退焦点覆盖记忆。
- 模拟器验收：首页海报 → 详情 → 返回回到原海报；设置 → 子页 → 返回回到原行；首页任意行 → 导航栏 → 右键回到该行。

## 播放器（0.4.0）

按用户要求参照 YouTube TV 的交互重做。视频画面、弹幕（`DanmakuView`）与外挂字幕仍为 View，其上叠加一个 `ComposeView`（`ui/player/PlayerOverlay.kt`），状态集中在 `PlayerUi`，用户意图通过 `PlayerActions` 回到 `PlayerActivity`；方向键全部由叠加层处理，Activity 只接收媒体键。

| 状态 | 按键 | 行为 |
| --- | --- | --- |
| 画面上没有控件 | 确定 | 暂停/继续并呼出控制栏 |
| | 左 / 右 | 后退 / 前进 10 秒；1.2 秒内同方向连按累加，屏幕一侧圆形提示“30 秒”，底部细进度条闪现 |
| | 按住右 | 临时 2 倍速，顶部提示；松开恢复原倍速（不写入设置） |
| | 上 / 下 | 呼出控制栏 |
| 控制栏 | 进度条左右 | 预览目标时间（气泡显示），连按加速：10 → 30 → 60 → 120 秒，且不小于总时长 1/200；停手 0.6 秒后跳转 |
| | 进度条下 | 固定落到播放/暂停键 |
| | 按钮行 | 上一集、播放/暂停、下一集，右侧选集、字幕、弹幕（圆点表示开启）、倍速（标签显示当前值）、更多设置；聚焦按钮白底黑图标放大并在下方淡入文字 |
| | 再向下 | 选集栏展开，整个控制区上移，焦点默认落在当前集；字幕暂时隐藏以免重叠 |
| 设置面板 | 确定 / 返回 | 右侧滑入，当前值带勾；选择后若进入下一级则保留上一级，返回键逐级退回，最后一级关闭回到画面 |
| 本集结束 | — | 有下一集：5 秒环形倒计时卡片，“立即播放”默认聚焦，“取消”停在本集结尾；没有下一集：“已经播放完毕”，可重新播放或退出 |

返回键顺序：设置面板逐级 → 取消连播倒计时 → 隐藏控制栏 → 退出播放器。加载中、失败或播放完毕时返回直接退出。控制栏在播放中 5 秒无操作自动隐藏，暂停时常驻。

细节：
- 遥控器确定键“按下时触发上一个界面的动作、抬起时才触发点击”，新出现的连播/结束卡片在 0.6 秒内忽略点击，避免一次按键穿透两层。
- Media3 自带的缓冲转圈已关闭，加载与缓冲统一由叠加层绘制；磁链播放时缓冲提示下方显示下载速度与已下载比例。
- 网络来源（0.5.1 起）缓冲时，转圈下方显示“网络 x MB/s · 视频约 y MB/s”，网速持续跟不上视频码率时再加一行说明（会多缓冲一些再继续，暂停一会儿可以提前缓冲）；控制栏右侧的状态文字在缓冲时也带上这行速度。“更多设置”新增“网络读取”：多连接（3 个连接分段下载）/ 单连接，拖动进度或重新打开后生效。缓冲策略与实测见[功能状态](功能状态.md)“局域网网络播放”。
- 选集栏卡片：集数大号数字（从文件名识别“第N集 / EPN / - N”，否则用队列位置）、标题、“正在播放”徽标、观看进度条，看完显示“已看完”。

## 焦点问题修正（0.4.0）

- `FocusRequester.requestFocus()` 在新版 Compose 返回 `Boolean`，不会因为目标未挂载而抛异常；此前用 `runCatching{}.isSuccess` 判断成功，导致“请求了但没聚焦”被当成成功。现在统一检查返回值，`requestContentFocus` 改为挂起函数，在约 2 秒内逐帧重试，等数据加载完的列表出现后再聚焦。
- 页面切换时旧页面被移除，系统会把焦点临时塞给左侧导航（甚至不是当前栏目）。导航栏的“停留 180ms 切换栏目”在延迟后再次确认焦点仍在导航栏且不在页面切换中，避免从媒体库进入目录后被自动切到“番剧”或“设置”。
- 从导航栏按右键进入内容区时，确认焦点确实落在当前页面（每个页面包一层焦点组并记录焦点所在页面），旧页面退场动画期间残留的目标不再算成功。
- 导航栏自己发起的栏目切换不再把焦点拉回被选中的那一项，连续按下方向键不会丢键。
- 列表数据在后台刷新（例如从播放器返回时 `refreshEpoch` 递增）时保留旧内容，聚焦的条目不会被移除，焦点不会掉到导航栏。
- 资源搜索结果页的筛选标签与计数固定在列表上方，不再被 TV 列表的“焦点居中”滚动挤出视野。

## 片库海报墙（0.5.0）

按用户要求把扫描出的视频组合成一部部作品，做成类似 NAS 影音应用的海报墙，点进作品像番剧详情页一样选集播放。

**归并与识别**（规则在 `core`，网络与持久化在 `app/data`）：

- `MediaNameParser` 从文件名和目录名解析作品名、季、集号、特别篇与特典标记、年份和压制标签；`LibraryGrouping` 把同名同季的正片归为一部作品，特别篇并入同名作品，特典（菜单、无字幕 OP/ED、PV、特典目录）并入同名作品或所在目录的作品，带标签或年份的单片是电影，其余按目录合成“其他”。作品键只由作品名、季与年份推出，重新扫描后不变。
- `LibraryRecognizer` 在后台识别：扫描完成或打开媒体库时开始，每部作品取一个样本文件读取前 16MB 特征，32 个合并成一次批量精确匹配；没有精确结果再单独模糊匹配一次、按名称搜索一次。识别成功后取作品资料与官方剧集表，按集号把本地文件绑定到官方剧集（存为“片库绑定”，手动绑定优先），播放时直接下载弹幕。服务按应用分配接口额度，额度用尽时暂停 30 分钟，作品保持“待识别”，不会被误标为“未识别”。

**海报墙（媒体库首页）**：

| 区域 | 内容与按键 |
| --- | --- |
| 顶部展示区 | 随焦点显示作品名、类型 / 集数 / 已看 / 评分和简介，背景是模糊海报 |
| 工具行 | 添加媒体源、索引与扫描、我的收藏、打开磁链、各媒体源（进入目录浏览）；初始焦点在第一张 |
| 筛选行 | 全部 / 剧集 / 电影 / 其他 / 未识别 / 已隐藏，带数量，只显示有内容的项；下方显示识别进度，中断时提供“重新识别” |
| 海报 | 识别成功用官方海报与作品名，未识别用标题生成占位封面；封面底部是已看比例或电影观看进度；确定打开作品页 |

从作品页返回时回到原来的海报；那部作品被隐藏后，焦点落到同一位置的海报。识别出新作品时海报墙自动刷新，扫描进行中每 9 秒刷新一次。横向列表向左多留 16dp 绘制区（`bleedStart`），首张卡片聚焦放大后边框不再被裁掉，首页各行同样受益。

**作品页**：左栏海报、名称、评分 / 类型 / 待识别徽标、简介与文件统计；右栏按钮行“继续播放 第 N 集”（最近一集没看完就续播，看完就下一集）、“番剧资料”（已识别时进入番剧详情）、“重新识别”、“隐藏 / 取消隐藏”，下面是正片（官方剧集名、文件名、大小、进度）、特别篇和特典。确定从该集开始连播本作品（特典单独成队列），长按打开文件操作；下一集标“下一集”，看到一半标“继续”。返回本页时回到原来的剧集行。

**重新识别**：顶部可在手机修改名称，或“自动识别”忽略已有结果重来；下方海报网格是样本文件的匹配候选与名称搜索结果，选中后作品改为手动指定，自动识别不再覆盖。

**首页**：新增“我的片库”行（最近看过的作品在前，不含个人视频与隐藏的作品）；继续观看中属于片库的视频显示作品名、集数与海报。

## 调试桥（tools/bridge）

云端会话无法直接访问 Mac 上的模拟器（Mac 上同时连着其它 adb 设备时，桥接命令通过 `ANDROID_SERIAL=emulator-5554` 指定模拟器），`tools/bridge/tv-bridge.sh` 在 Mac 上监视 `queue/*.cmd` 并执行其中的 shell 命令，输出写回 `.out`。配合它可以安装分块同步的 APK、用 `adb shell input keyevent` 模拟遥控器、`screencap` 截图，并用 `submit-form.sh` 代替手机提交表单。该目录仅用于开发调试，不进入发布包。`stall-test.sh`（用法：`TV=电视地址:5555 tools/bridge/stall-test.sh [秒数]`）在实体电视上播放“继续观看”第一项，每秒记录播放状态与 Wi-Fi 接收速度，结束时输出 `PlaybackNet` 日志，用于测网络播放的卡顿规律（会推进该视频的观看进度；不截图）。
