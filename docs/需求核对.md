# 需求来源与交付范围核对

核对日期：2026 年 10 月 13 日。

独立 TV 重写应覆盖原产品明确承诺的功能和用户确认的 TV 交互要求。此前把“只有 Media3”“在线字幕以后再做”等实现缺口写进规格，会弱化原目标；把 NFS、SFTP、Watch Next、未完成的 Torrent 等自行扩展项全部列为必须门槛，也会扩大原目标。本轮修正规格边界，同时保留真实功能缺口，不以改文档代替实现。

旧产品证据仅来自父项目 [README](https://github.com/xyoye/DanDanPlayForAndroid/blob/master/README.md) 和 [远程控制产品文档](https://github.com/xyoye/DanDanPlayForAndroid/blob/master/document/ScreenCasting.md)，没有读取旧源码、资源、数据库模型或构建脚本。新工程源码可以用于核对实际接线；类名、接口存在和单元测试文件存在都不能单独证明正式服务或真实设备已经验收通过。最终实现及验证记录以 [功能状态](功能状态.md) 为准。

## 原产品明确功能

| 产品说明 | TV 重写应保留的目标 | 验收要点 |
| --- | --- | --- |
| README：IJK、EXO 双内核切换，适配常见视频格式 | 提供两个真实解码后端，可按兼容性需要切换；新工程选用 Media3 与 VLC | 播放中及失败后切换、位置与播放意图恢复、倍速和音量、选轨、释放与远程控制；保留双内核目标，不要求沿用旧库 |
| README：本地播放器，局域网、FTP、WebDAV；Stream 模块含 SMB | 本地授权目录和网络目录浏览播放，覆盖 SMB、FTP、WebDAV | 中文/子目录、凭据、随机定位、附件读取、失效授权、连接失败及恢复；真实服务互操作需单独验证 |
| README：弹幕自动匹配、搜索、下载 | 使用真实官方匹配与下载服务，自动失败后可手动选番剧和剧集 | 正式鉴权、真实文件指纹、名称候选确认、暂停/倍速/定位/切集后的同步；不得伪造哈希或数据 |
| README：弹幕大小、速度、描边、透明度；关键词及正则屏蔽 | 遥控器可调样式和规则，错误正则可恢复 | 实际画面生效、规则持续保存、密集数据性能、异步结果隔离；明确正则库的语法差异 |
| README：字幕自动匹配、搜索、下载 | 接入正式在线字幕服务，并保留导入文件/地址的路径 | 自动匹配的可靠性、名称候选、下载、缓存、服务认证/配额/错误恢复；只有表单和接口不算完成 |
| README：外挂字幕，大小、描边、颜色 | 外挂和内嵌字幕可选择，字号、描边与颜色可调整 | 不仅能显示文字；逐项核验样式生效和不同内核差异。ASS 文件自带样式与用户设置的优先级应明确 |
| README：每周番剧、番剧搜索、番剧详情；Anime 模块提及季番 | 官方每周、搜索、详情与季度资料浏览 | 正式 API 返回真实列表/详情/剧集，空态与失败态可返回、重试；番剧资料不代表提供视频资源 |
| 远程文档：状态、播放/暂停/恢复、绝对/相对定位、倍速、音量、停止/退出 | 手机与 TV 操作同一播放会话，返回真实状态和缓冲进度 | 前后台、失败状态、命令超时、停止释放与进度保存；不能回报假成功 |
| 远程文档：弹幕大小、速度、透明度、描边、滚动/顶部/底部、最大数量/行数 | 提供完整远程弹幕配置，并与 TV 设置即时一致 | 每个字段需实际生效，不能因换 API 路径而缩减原行为；数量与窗口可采用公开的性能预算 |
| 远程文档：云屏蔽，原始/简体/繁体语言 | 真实云屏蔽数据和简繁转换 | 确认服务与字典，区分本地规则和云规则、原文和已转换文本；外部条件或未完成项必须如实报告 |

远程文档还包含亮度字段和亮度命令。TV 上需针对可控制的设备能力定义语义；无能力时明确报告不支持及原因，不能伪造成功。这一设备限制不应被扩大为对其他远程功能的删减。旧协议的 AES 密码细节未给出，新版可定义自己的配对和 API，但不能声称已兼容旧加密客户端。

## 用户确认的 TV 要求

独立包名、存储和构建，可与旧应用共存；全部页面按方向键、确定、返回和媒体键设计，具有稳定的初始焦点、返回路径以及加载、空态和失败态。所有文字输入统一由手机专属表单完成，TV 展示本次操作的二维码；数字、开关、选轨和系统文件授权继续由遥控器操作。

每次输入生成独立请求与地址。表单只能提交当前操作，成功、取消或过期后结束，离页和切集取消旧请求，迟到响应不得作用于下一操作。账号密码和密钥不回传网页，留空保留已存值，显式清除才能删除。独立遥控首页提供播放控制和 URL 投送，启动应用自动准备局域网服务，停止和重新配对撤销旧连接。这些是用户补充的行为契约，不能用旧文档未描述手机表单为由删减。

## 本轮补齐与验证边界

下表说明本轮在新工程中接入的能力。这里的“接入”是源码与使用入口的核对结果，不代表本轮构建、正式服务或真机验收已通过。测试命令、样本、设备、结果和外部条件应另记在功能状态中。

| 能力 | 本轮接入范围 | 必须区分的证据与外部条件 |
| --- | --- | --- |
| Media3 / VLC | 两个解码器、统一会话、默认内核选择、播放中和失败时切换；认证来源适配 | 规则测试验证状态恢复不等于两个内核的所有协议/轨道/格式已通过；带认证的 HLS/DASH 与不同设备编码仍需样本 |
| 收藏与真实媒体库索引 | 收藏持久化、递归来源扫描、索引、取消及预算状态、名称搜索和过滤 | 静态演示列表不算索引；需验证实际本地和网络目录、重扫、失败、删除来源与取消后的索引一致性 |
| 版本化备份 | 公开备份排除凭据；密码加密备份可包含网络凭据及开发者密钥；导入校验、预览与原子替换 | 损坏、错误密码、未知版本、非法地址及旧异步回写不能破坏现有数据；本地 URI 授权和本机 Keystore 密钥不能跨设备复制 |
| 季度番剧 | 从官方 API 获取季度列表及对应番剧，接入详情入口 | API 测试夹具不等于公网季度服务通过；正式鉴权、空季度和服务错误需有记录 |
| OpenSubtitles 在线字幕 | 正式 API 的独立凭证配置、名称/语言搜索、登录下载和本机缓存 | 需要用户自己的 API Key、账号、应用名称和可用配额；本轮没有正式账户成功记录时，必须写“尚未验证正式服务”，不能写已通过 |
| 可靠字幕自动匹配 | 读取视频真实大小与首尾片段，计算提供方文件指纹；仅唯一且语言符合的指纹结果自动下载 | 大小未知、无法完整读取或没有可靠结果时不自动下载，保留手动搜索；需要真实匹配样本验证，不能用名称相近冒充匹配 |
| 字幕编码与 ASS/字体 | 自动检测和手选 UTF/GB18030/Big5/Shift_JIS 等编码，导入 TTF/OTF；VLC 原生字幕路径处理 ASS 样式与字体附件 | 字符检测是推断，允许手工纠正；VLC API 与字体目录接入不能证明所有 ASS 特效/附件字体已通过；须用对应媒体和画面验收 |

备份包含来源、设置、收藏、索引、观看进度和剧集绑定；视频、字幕文件、本机 Keystore 密钥与在线字幕服务凭证不打包。公开备份与密码备份的差异应在导出和恢复前显示，恢复后对本地目录重新授权及重新配置字幕服务提供入口。

## 完整性必查项

字幕描边是原 README 明确承诺的可调整能力，不能将“默认描边能显示”视为完成。交付时应核验可操作设置、实际画面生效以及不同内核/ASS 样式的优先级；没有对应证据时，在功能状态中明确列出缺口。

远程 `/api/config` 应逐项覆盖旧文档的弹幕设置行为。云屏蔽与简繁转换具有原产品文档依据，不能降为随意扩展；应分别记录数据来源、设置入口、远程一致性及实际验证。在证据齐备前不得宣称旧功能全部覆盖。这里保留需求核对规则，当前接入和验收结果统一记录在功能状态中。

SMB 真实 NAS、全部字幕格式/样式、多音轨/字幕轨、不同编码媒体、真机授权和低性能设备仍需要各自的验收证据。某一网络视频能播放、全部单元测试通过或 APK 构建成功，不能替代这些验证。

## 不应误加的完成门槛

| 项目 | 旧文档证据与处理原则 |
| --- | --- |
| Torrent 下载 | README 明确标为未完成；不能把它视作旧版已可用功能，或因新工程未完成就否定此次明确范围。若用户需要，可独立规划引擎、队列和资源控制 |
| 用户登录注册 | README 明确相关接口已关闭，编译安装后不可用；开发者应用鉴权与 OpenSubtitles 账户配置不等于恢复该账号模块。新增账号需另定服务契约 |
| 磁链解析与下载队列 | 模块说明提到磁链解析，没有给出可用流程和验收契约；允许扩展，不据模块名推断已完成下载功能 |
| NFS、SFTP、DLNA、自动发现 | 原功能说明没有明确承诺；与已承诺的 SMB、FTP、WebDAV 分开，不以新增协议取代这些协议的验收 |
| Watch Next、镜像投屏、手机文件转发、旧数据库自动迁移 | 此前规格自行追加或旧文档没有充分契约；可以扩展，不能作为原功能不缺漏的门槛。URL 投送按用户确认的新版要求验收 |
| 全部编码、无条件 4K/HDR、全部 ASS 特效 | 取决于媒体、后端和设备，不作无条件承诺；应给出具体支持证据和恢复路径，不以硬件边界掩盖可实现的样式或控制缺口 |

这些方向保留扩展空间，后续可调整 UI、播放器、存储、协议库和模块划分。任何新增范围都应有需求来源和验收契约，任何已有明确范围的缺口都应在真实能力记录中呈现。
