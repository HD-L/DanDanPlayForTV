# 独立 TV 重写实施与验收计划

## 目标与交付边界

本工程按电视观看与遥控器操作重新实现，不复制旧工程实现。产品范围只从原 README、产品说明和用户确认中提取；原文没有明确承诺的扩展功能不擅自升级成验收门槛。独立包名、构建和本机数据使新工程可与旧应用并存。详细行为契约见[产品规格](产品规格.md)，来源及门槛依据见[需求核对](需求核对.md)。

首个可试用版本为 0.2.0；0.3.0 把界面层重写为 Compose for TV（见[界面层重写](界面层重写.md)），构建、安装和当前能力记录见[功能状态](功能状态.md)。后续顺序见[原版功能清单与归属讨论](原版功能清单与归属讨论.md)第 14 节。TV 页、播放器、存储、来源协议和手机网页属于可以继续替换的实现选择；领域行为和用户交互契约不要求跟随具体库或类名。

## 已完成的实现范围

- 独立 Gradle 工程、纯 Kotlin core、原生 TV 页面、媒体库、番剧和设置页面；采用稳定焦点、方向键、确定和返回完成主要操作。
- 本地授权、HTTP/HTTPS、WebDAV、SMB、FTP 来源；手机表单可选类型并显示条件字段。TV 系统目录授权仍在 TV 上完成。
- Media3/VLC 播放后端接入统一播放会话，集中管理进度、控制、切集、字幕与弹幕。
- 本机字幕/弹幕、OpenSubtitles 和弹弹play服务适配，字幕解码/缓存、弹幕规则与语言转换。
- 收藏、自然排序、递归索引、搜索过滤、有限播放队列，以及公开/密码加密备份恢复。
- 应用启动准备局域网 Web 服务；每次文字输入各有专属二维码与表单，遥控首页独立。表单成功、取消、过期或离页后结束，不跟随电视下一项输入。
- 自动化和 TV 模拟器验收按不同证据层次记录；正式服务、实体手机和设备结果不由单元测试代替。

## 验收方法

先运行 core 和 Android JVM 测试，再构建 APK 并运行 lint；Node 测试执行网页实际脚本。协议夹具验证媒体读写和错误路径。TV 模拟器使用方向键及播放器样本检查导航、焦点、表单入口、输入结束、续播和画面。正式账号服务、实体手机相机扫码、真实 NAS、播放器编码兼容及实体低性能设备分别记录，不能互相代替。

可在 `tv-rewrite/` 根目录执行：

```bash
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --max-workers=2
node --test tools/tests/remote-page.test.mjs
```

2026 年 10 月 13 日版本 0.2.0 结果：167 项 Kotlin 测试与 6 项网页测试通过，lint 0 错误、43 条警告；APK 已安装并在 4 GiB Android TV 模拟器完成表单提交、列表刷新和 H.264/AAC 样本播放。2 GiB 模拟器首次启动出现无焦点 ANR；OpenSubtitles 正式用户账户、实体电视/手机、VLC 真实画面及 SMB NAS 未通过本轮设备验收。逐项证据和外部条件见[功能状态](功能状态.md)。

## 仍需设备或外部条件支持的验收

1. 在常见 2 GiB 实体 Android TV 上重复首次安装和首次启动，观察启动耗时、焦点、内存及是否出现 ANR。
2. 用实体手机相机在真实局域网扫描每种文字表单，确认屏幕尺寸、密码留空/清除、提交结束和电视焦点返回。
3. 使用用户授权的 WebDAV、FTP、SMB NAS 与本地文件提供方，验证凭据、中文目录、随机定位、授权撤回和断网恢复。
4. 在目标电视上切换 Media3/VLC，按目标媒体验证轨道、编码、外挂字幕/ASS、音量、seek 和进度保存。
5. 若用户提供独立 OpenSubtitles API Key、账户及可用配额，再验证其正式登录、真实搜索、可靠文件指纹与下载；不得使用弹弹play 凭证代替。

上述项目是环境和设备验收事项，不作为继续堆叠架构或禁止重构的理由。不得将未提供的账号当作代码完成条件，也不得将未在设备上验证的行为标成通过。
